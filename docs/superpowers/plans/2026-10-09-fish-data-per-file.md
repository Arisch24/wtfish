# Fish Data: One JSON File Per Fish — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the single `apps/web/data/fish.json` array with one JSON file per fish in `apps/web/data/fish/`, with the built site unchanged.

**Architecture:** The Astro content collection `fish` currently uses the `file()` loader on one JSON array. Switch it to the `glob()` loader over `data/fish/*.json`; each entry's id (and so its URL `/fish/<id>/`) comes from its filename instead of an `id` field. Pages, schema and styling do not change.

**Tech Stack:** Astro 7.3 content layer (`astro/loaders` `glob`), `astro/zod`, pnpm, Node 22.

**Spec:** No separate spec doc — requirements come from the 2026-10-09 discussion: one JSON file per fish, data stays outside `src/` but inside `apps/web/`.

## Global Constraints

- Data lives in `apps/web/data/fish/` — inside `apps/web`, outside `src/`.
- One fish per file; filename is the fish id: lowercase kebab-case, e.g. `clown-anemonefish.json`.
- Files contain no `id` field — the filename is the single source of the id.
- Package manager is pnpm — do not use npm or yarn.
- Work on branch `refactor/fish-per-file`, created from `main`; merge back into `main` only after the user approves.
- Commit messages follow Conventional Commits (enforced by the husky `commit-msg` hook) — never bypass it with `--no-verify`.
- No changes to `src/pages/**`, `src/layouts/**` or the zod schema fields.

## Review Focus

- **Built output must not change.** Every URL `/fish/<id>/` and every page's HTML must be byte-identical before and after (pinned by the `diff -r` in Task 1 Step 6).
- **Broken JSON in one file** should fail the build with an error naming that file, not silently drop the fish (pinned in Task 1 Step 7).
- **Missing required field** (e.g. no `scientificName`) should fail the build (pinned in Task 1 Step 7).
- **Uppercase or spaced filenames** (`Clown Fish.json`) would get a slugified id (`clown-fish`), so the URL silently differs from the filename — prevented by the naming rule in Global Constraints and noted in `data/fish/README.md` (Task 1 Step 5).
- **Non-JSON files in the folder** (e.g. `README.md`, `.DS_Store`) must be ignored by the loader — pinned by keeping `README.md` in the folder during the Step 6 diff.

- [ ] **Step 2: Split `data/fish.json` into one file per fish (one-off, not committed)**

```bash
mkdir -p data/fish && node -e '
const fs = require("fs");
const all = JSON.parse(fs.readFileSync("data/fish.json", "utf8"));
for (const { id, ...rest } of all) {
  if (!/^[a-z0-9]+(-[a-z0-9]+)*$/.test(id)) throw new Error("bad id: " + id);
  fs.writeFileSync(`data/fish/${id}.json`, JSON.stringify(rest, null, 2) + "\n");
}
console.log(all.length + " files written");
'
ls data/fish | wc -l
cat data/fish/barramundi.json
```

- [ ] **Step 3: Switch the collection to the glob loader**

In `src/content.config.ts`, replace the import and loader lines so the file reads:

```ts
import { defineCollection } from 'astro:content';
import { glob } from 'astro/loaders';
import { z } from 'astro/zod';

const fish = defineCollection({
	loader: glob({ pattern: '*.json', base: './data/fish' }),
	schema: z.object({
		commonName: z.string(),
		scientificName: z.string(),
		family: z.string(),
		category: z.enum(['aquarium', 'game']),
		water: z.enum(['freshwater', 'saltwater', 'brackish', 'migratory']),
		maxLengthCm: z.number().positive(),
		summary: z.string(),
	}),
});

export const collections = { fish };
```

```markdown
# Fish data

One file per fish. The filename is the fish's id and URL:
`clown-anemonefish.json` → `/fish/clown-anemonefish/`.

- Do not add an `id` field — the filename is the id.

  the build fails if a file is missing a field or has an invalid value.
```
